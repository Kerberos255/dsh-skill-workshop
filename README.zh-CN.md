# DSH 技能工坊（Skill Workshop）

[English](README.md) · [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) · [安全说明](SECURITY.md)

用于管理 DSH 原生技能，并从已完成的任务**自动提炼可复用工作流程**。模型提出候选技能，插件负责核验、发布、容量限制与恢复；无需每次弹窗要求人工确认。

## 主要功能

- 查看、编辑、导入原生 `SKILL.md` 技能，支持 Markdown、目录和受支持的归档格式。
- 从工作区已完成、来源可核验的真实任务中学习；简单闲聊、失败和取消的任务跳过。
- **默认自动学习、自动发布**：同一方法需至少两个独立完成的成功任务实例，且能对应原始用户需求与助手结果；同一轮反复归纳不计作新证据。
- 人工编辑过、其他插件创建或外部修改的技能不会被自动覆盖。
- 发布采用意图账本、路径锁和文件校验；断电/中断后优先核对现有文件，不用模型盲目覆盖。

## 安装与使用

需要 DSH 原生技能 Registry、Agent 与 Session 服务；实际运行环境看 [package.json](package.json)。

```sh
dsh plugin --profile desktop add github:Kerberos255/dsh-skill-workshop
```

在「设置 → 插件 → 技能工坊」选择保存范围（当前项目 `.dsh/skills` 或用户 `DSH_HOME/skills`），确认自动学习及发布开关，即可正常使用 DSH 完成任务。首次只保留简短经验与出处，不生成完整技能或人工待审提案；第二个独立成功任务补充同一方法的证据后，才生成完整技能并自动发布，无需逐项审批。手动导入、编辑或发生文件冲突时仍保留人工审阅入口。

## 如何防止无限增长？

| 机制 | 默认规则 |
| --- | --- |
| 同工作区待验证自动候选 | 最多 **64** 个 |
| 同工作区自动受管技能 | 最多 **64** 个 |
| 候选未出现新独立证据 | 默认 **21 天**后归档，设置项 `candidateIdleDays` |
| 学习冷却和每日次数 | **60 分钟**、每日最多 **8 次** |
| 闲置受管技能 | **90 天**退役，额外保留 **7 天** |
| 自动整理已处理记录 | **180 天**裁剪 |
| 待整理任务 / 已处理任务指纹 | 每工作区最多 **128 / 512** 条 |
| 候选归档摘要 | 最多 **256** 条、**180 天** |
| 已处理提案历史 | 默认 **180 天 / 500 条**，旧配置明确设置的限制仍保留 |

设置页可以调整对应上限。达到受管技能上限后，自动创建新技能会暂停，仍可继续更新未被人工修改的旧技能。人工技能和外部技能不在清理范围；关闭闲置淘汰会保留原有技能文件。

**注意**：两个独立成功轮次提供的是“来源与重复经验”门槛，不等于技能已在真实环境重新执行两次，也不代表外部客观验收通过。

## 候选归并与学习排队

模型会收到相关候选的稳定编号和摘要；适用条件、操作流程与验证方法相同的后续任务补证已有候选，措辞、版本或标的变化不会自动成为新技能。只有主题相近但方法不同的经验保留为不同候选。“继续、重试”等跟进、重复观察和同一已记录任务不增加证据。入池时同时检查可复用性、实际验证依据和方法具体程度，模型评分仍须有可核验的成对出处支撑。

成功任务先记录出处编号，再检查冷却、每日次数和是否忙碌，避免节流期间丢掉补证机会。空闲时每分钟检查，一次请求最多整理四组完整任务，且每次最多为一个达标候选生成完整技能。草稿失败保留已核验的证据；自动失败按小时退避，最多三次，设置页手动学习可以重新尝试。

满池先归档至少七天未强化的低分单证据候选，保护新候选、双证据候选和恢复中的发布。仍无空位时仅补证；没有相关候选的任务会在调用模型生成前暂缓。发布、拒绝和过期会释放容量；归档摘要与有界任务指纹在保留期内防止旧任务重复入池。人工待审提案单独保留。

**0.1.15 升级**会原样保留旧候选的提案引用和证据，补充稳定编号、摘要与已处理来源指纹；不会仅因标题相似就把旧候选合并或晋升。升级前备份本地插件状态，安装后完整重启 DSH 加载新版。

## 模型 JSON 容错与重试

自动学习接受一个完整 JSON 对象、单个 JSON 代码围栏，或被少量说明文字包裹的唯一完整 JSON 对象。不会编造缺失字段或来源证据，也不会降低两个独立成功任务的自动发布门槛；简短经验与完整草稿阶段均使用同样的有界格式重试。只有在模型**正常完成但返回格式不合法 JSON**时，才使用同一份核验过的来源材料最多再生成一次；取消、模型报错、输出 Tokens 截断不触发格式重试。

诊断仅记录阶段、尝试次数、格式分类、输出字符数和 Token 上限，不保存模型生成原文、对话或凭证。当前 DSH 通用模型请求类型没有 JSON Schema 响应格式选项，因此使用严格提示词与确定性解析器。CI 运行无宿主依赖的出处、SQLite 队列、迁移、解析和设置页重建测试；流式模型与 Registry 回归测试需在可解析匹配 DSH SDK 的环境中运行。

## 数据、回退和测试

状态保存于 DSH 本地 `skill-workshop/state.sqlite`，技能文件落在选定的原生技能目录。进程中断后核对文件哈希并尝试恢复；若外部改动或路径不一致，暂停自动恢复并提示处理冲突。未发布候选不等于已安装技能。

使用 Node 24 运行 `npm test` 检查便携逻辑，无需 DSH 宿主或网络调用。在可解析匹配 DSH SDK 的环境中运行 `npm run test:host` 检查模拟模型流与 Registry；真实提供商和桌面行为仍需单独验证。配置：[config.example.json](config.example.json) · 安全：[SECURITY.md](SECURITY.md)。
